HeroDevs · Never-Ending Support

지원이 끝난 오픈소스도,
안전하게 계속

HeroDevs Never-Ending Support(NES)는 이미 운영 중인 지원 종료(EOL) 오픈소스를 CVE-free drop-in 대체 버전으로 바꿔, 코드 수정 없이 보안 패치를 계속 받게 해 줍니다. 앨리웍스는 HeroDevs의 한국 공식 총판입니다.

Why it matters

지원 종료(EOL)는 끝이 아니라
보안 공백의 시작입니다

오픈소스 프로젝트가 EOL에 도달하면 더 이상 보안 패치가 나오지 않습니다. 하지만 그 위에서 돌아가는 업무 시스템은 내일도 운영되어야 합니다.

패치되지 않는 CVE가 쌓입니다

EOL 이후 새 취약점이 공개되어도 공식 패치는 나오지 않습니다. 직접 쓰는 라이브러리뿐 아니라 의존성 깊숙한 곳(transitive)까지 위험이 누적됩니다.

감사 · 컴플라이언스 리스크

지원이 끝난 소프트웨어는 보안 감사와 규제 대응에서 지적 사항이 되기 쉽고, 조치 근거를 설명하기도 어렵습니다.

쫓기듯 하는 마이그레이션

메이저 버전 업그레이드는 대규모 코드 수정과 회귀 테스트를 동반합니다. 일정에 쫓겨 서두르면 오히려 장애 위험과 비용이 커집니다.

Never-Ending Support

쓰던 버전 그대로,
보안 지원은 끝없이

NES는 특정 EOL 프레임워크에 의존하는 동안 계속되는 상용 보안 지원입니다. HeroDevs 엔지니어가 SLA에 따라 패치를 만들고 검증해, 이미 쓰고 있는 버전의 CVE-free 대체 버전으로 제공합니다.

Drop-in replacement

코드 수정 없는 교체

패키지 매니저가 NES 레지스트리를 바라보게 한 뒤 다시 빌드하면 됩니다.

  • 같은 버전 라인 · 공개 API 유지
  • 애플리케이션 코드 변경 없음
  • CI 파이프라인 변경 없음
Continuous patching

새 CVE마다 새 릴리스

지원 버전에서 CVE가 발견·수정될 때마다 새 NES 릴리스가 나옵니다. HeroDevs에 따르면 지금까지 대개 공개 후 수 시간 안에 제공됐습니다.

  • 보안 · 호환성 패치
  • 수정마다 VEX 문서 제공
  • 서명된 법적 증명서(attestation)
Enterprise SLA

약속된 시간 안에 대응

구독에는 패치뿐 아니라 전문가 지원과 엔터프라이즈 SLA가 포함됩니다.

  • Critical 수정은 발견 후 14일 이내 처리
  • 보안 · 장애성 이슈 당일 응답
  • 컴플라이언스 업데이트 포함

How it works

레지스트리만 바꾸면,
전환은 몇 분이면 충분합니다

같은 버전 라인과 공개 API를 그대로 유지하기 때문에 애플리케이션 코드도, CI 파이프라인도 바꿀 필요가 없습니다.

  • npm · Maven 등
  • Nexus · Artifactory 가이드
  1. STEP 01

    진단 · 스캔

    무료 EOL 스캔과 EOL Dataset으로 운영 중인 의존성 가운데 지원이 끝난 기술과 버전을 찾아냅니다.

  2. STEP 02

    레지스트리 전환

    npm, Maven 같은 패키지 매니저가 HeroDevs NES 레지스트리를 바라보도록 설정합니다.

  3. STEP 03

    재빌드 · 배포

    평소처럼 빌드하고 배포합니다. 같은 버전 라인의 NES 빌드가 기존 패키지를 대체합니다.

  4. STEP 04

    지속 패치 · 지원

    새 CVE가 수정될 때마다 NES 릴리스와 VEX 문서, 서명된 증명서를 받고 SLA에 따라 지원받습니다.

switch-to-nes — 예시
# 1. 현재 의존성 확인 $ npm ls angular └── angular@1.8.x EOL · 보안 패치 중단 # 2. NES 레지스트리로 전환 $ npm config set registry <HeroDevs NES 레지스트리> # 3. 그대로 다시 빌드 $ npm install && npm run build angular 1.8.x · NES 빌드로 교체 ✓ 코드 수정 없이 재빌드 완료 ✓ CVE 패치 적용 · VEX 문서 제공

설명을 위한 예시입니다. 레지스트리 주소와 실제 설정 방법은 HeroDevs가 제공하는 가이드(npm · Maven, Nexus · Artifactory 등)를 따릅니다.

Evergreen Platform & Tools

프레임워크 하나에서
애플리케이션 전체로

NES가 특정 프레임워크를 지원한다면, Evergreen Platform은 애플리케이션이 의존하는 모든 EOL 의존성을 저장소 단위로 다룹니다. 무엇이 EOL인지 확인하는 무료 도구도 함께 제공됩니다.

Evergreen Platform

저장소 전체를 EOL 위험 없이

출시 시점 npm 생태계 지원

GitHub App과 GitHub Actions 워크플로 하나로 설치하면 저장소를 지속적으로 스캔합니다. 지원이 끝난 패키지에 CVE가 생기면 보안 대체 버전으로 교체하는 Pull Request를 엽니다.

  1. 1설치GitHub App + Actions 워크플로
  2. 2지속 스캔모든 EOL 의존성 추적
  3. 3자동 PR보안 대체 패키지로 교체
  4. 4증빙 보관VEX · 법적 증명서를 compliance 폴더에
Open EOL 의존성을 보안 대체 버전으로 교체 예시
  • package.json 수정
  • compliance / VEX 문서 추가
  • compliance / 법적 증명서 추가

Evergreen은 출시 시점 기준 npm 생태계만 지원하며, 다른 생태계는 순차 지원 예정입니다(HeroDevs 발표). 기존 SCA 스캐너를 대체하지 않고 보완합니다.

    견적 · 트라이얼

  4. STEP 04

    도입 · 기술지원

    레지스트리 전환과 적용을 돕고, 이후 패치 적용과 갱신, 기술 문의를 국내 창구에서 지원합니다.

자주 묻는 질문

더 궁금한 점은 앨리웍스에 직접 문의해 주세요. 운영 환경에 맞춰 안내해 드립니다.

문의하기
EOL(End of Life)이란 무엇인가요?

오픈소스 프로젝트나 특정 버전이 공식 지원을 끝낸 상태를 말합니다. EOL 이후에는 새로운 취약점이 발견되어도 커뮤니티나 원 개발 조직이 보안 패치를 내놓지 않습니다. 예를 들어 Drupal 7은 2025년 1월 5일 공식 EOL을 맞았습니다.

NES로 바꾸려면 코드를 수정해야 하나요?

아니요. NES는 쓰던 것과 같은 버전 라인과 공개 API를 유지하는 drop-in 대체 버전이라, 애플리케이션 코드와 CI 파이프라인을 바꿀 필요가 없습니다. npm, Maven 같은 패키지 매니저가 HeroDevs NES 레지스트리를 바라보도록 설정하고 다시 빌드하면 됩니다(Nexus · Artifactory 가이드 제공).

어떤 기술을 지원하나요?

Spring · Struts · Tomcat 등 Java 생태계, AngularJS · Angular · Vue 2 · Bootstrap · jQuery 등 프론트엔드, Node.js, Drupal 7 · PHP, .NET, Django · Rails, PostgreSQL 등 폭넓은 기술을 지원합니다. 버전별 상세 목록은 위 지원 기술을 참고해 주세요. 목록은 수시로 바뀌므로 도입 전 앨리웍스가 최신 지원 여부를 확인해 드립니다.

가격과 라이선스는 어떻게 되나요?

HeroDevs는 고객 환경에 맞춘 맞춤 가격을 연 단위로 청구하며, 다년 계약도 가능합니다. 환경(서버)별 요금은 없고, 라이선스는 코드를 커밋하는 사용자 기준으로 산정되며 기명이 아니어서 양도할 수 있습니다.

NES 라이선스는 영구 라이선스여서 계약 기간이 끝난 뒤에도 그 시점의 최신 버전을 계속 쓸 수 있습니다. 소스 코드가 포함되고 텔레메트리나 라이선스 서버는 없습니다. 무료 트라이얼 버전이 있고, 비영리 · 교육 기관 할인도 있습니다. 정확한 견적은 앨리웍스로 문의해 주세요.

마이그레이션 대신 왜 NES를 선택하나요?

메이저 버전 업그레이드는 대규모 코드 수정과 회귀 테스트가 필요해 시간과 비용이 많이 듭니다. NES는 업그레이드를 포기하는 것이 아니라, 업그레이드를 준비하는 동안에도 보안 패치와 컴플라이언스 근거를 유지해 일정에 쫓기지 않게 해 줍니다. 업그레이드가 더 이상 의미 없는 레거시 시스템이라면 의존하는 동안 계속 지원받을 수도 있습니다.

Azul과 HeroDevs는 무엇이 다른가요?

Azul은 Java 런타임(JDK)을 제공합니다. Azul Platform Core는 TCK 인증 OpenJDK, Platform Prime은 고성능 JVM입니다. HeroDevs NES는 JDK를 제공하지 않고, 그 위에서 돌아가는 Spring 같은 프레임워크와 라이브러리, 그리고 JavaScript · PHP · .NET 등 다른 생태계의 EOL 오픈소스를 지원합니다.

두 제품은 겹치지 않고 서로를 보완합니다. 앨리웍스는 두 회사의 한국 공식 총판으로 Java 스택 전체를 함께 상담해 드립니다.

보안 스캐너가 NES 패키지를 취약하다고 표시하면 어떻게 하나요?

NES 버전은 공개 레지스트리에 없기 때문에 일부 스캐너가 원래 버전으로 인식해 경고할 수 있습니다. HeroDevs는 Mend.io 등 스캐너 벤더와 CVE 해결 데이터를 공유하고, 수정마다 VEX 문서를 제공해 실제 영향 여부를 확인할 수 있게 합니다.
