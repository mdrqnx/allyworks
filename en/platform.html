at an incredible value

How is Azul Zulu different from Azul Platform Core?

Azul Zulu is the OpenJDK build made by Azul. Azul Platform Core (formerly Zulu Enterprise / Embedded) is the enterprise product built on Azul Zulu builds, adding quarterly CPU and PSU security updates, legacy Java 6 and 7 support, IP protection and indemnification, and Standard or Premium technical support.

Do we need to change application code to migrate?

Azul Platform Core is a one-to-one drop-in replacement for Oracle Java SE, verified against the Java SE TCK. According to Azul, most server applications switch over by installing the new OpenJDK distribution, changing JAVA_HOME, and restarting. Azul Platform Prime likewise requires no code changes or recompilation.

Allyworks first confirms that migration will work in your environment through an upfront assessment and a PoC.

Which Java versions and platforms are supported?

The LTS versions Java 8, 11, 17, 21, and 25 are supported, as are STS releases, and Java 6 and 7 receive legacy production support. LTS versions get at least 8 years of production support (plus 2 years of extended support).

Supported operating systems include Linux, macOS, and Windows; supported architectures and environments include x64, ARM, and Alpine. You can install via package managers, container images, or direct download.

How do we get technical support?

As the Authorized Distributor of Azul in Korea, Allyworks provides consultation, migration, technical support, and maintenance directly in Korea, on top of Azul's support tiers.

Standard offers business-hours support with next-business-day response; Premium offers 24x7x365 support with an initial response within 1 hour.

What about end of life (EOL) for frameworks such as Spring?

Azul supports the JDK (the Java runtime). For end-of-life frameworks and libraries that run on top of it, such as Spring Boot, Spring Framework, Tomcat, Struts, and Log4j 1, you can keep receiving security patches through HeroDevs Never-Ending Support (NES). Because NES keeps the same version line and APIs, you simply change the repository settings in your package manager (such as Maven) and rebuild.
